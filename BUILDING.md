# BUILDING.md
Canonical Build + Editing Contract for Twitter Archive Book

This document defines the authoritative build process, file ownership boundaries, and invariants for the Twitter Archive static HTML book project.

---

# 1. High-Level Architecture

This project converts a Dec-2022 Twitter export into a static HTML "book."

There are **three independent layers**:

1. Data normalization + cleanup
2. Content generation (threads + compendium)
3. Book scaffolding + navigation

These layers must remain cleanly separated.

No script should duplicate logic that belongs to another layer.

---

# 2. Canonical Build Process

From repo root:

## Step 1 — Generate Compendium

```bash
python3 data/generate_compendium_chapter.py
```

This generates:

```
book/chapters/compendium.html
```

Responsibilities:
- Render singleton tweets
- Apply compendium-specific styling hooks
- Leave navigation patching to the book generator

It must NOT:
- Redefine global book structure
- Modify ToC
- Modify other chapters

---

## Step 2 — Generate Book Structure

```bash
python3 data/generate_book_html_with_titles.py
```

This:

- Regenerates thread chapters
- Regenerates:
  - `book/index.html` (Cover)
  - `book/chapters/title.html`
  - `book/toc.html`
  - `book/chapters/preface.html`
- Patches navigation into compendium
- Applies chronological ordering
- Applies chapter numbering

---

## Step 3 — Preview Locally

```bash
cd book
python3 -m http.server 8000
```

Then open: http://localhost:8000

# 3. File Ownership & Editing Rules

## A. Hand-Edited Files (Never Auto-Rewritten)

These files are human-owned content sources:

```
data/frontmatter/cover.html
data/frontmatter/title.html
data/frontmatter/preface.html
data/chapter_titles.json
data/url_overrides.json
book/style.css
```

Generators must read from these every run.

They must NOT:
- Overwrite them
- Reformat them
- Inject structural HTML into them

---

## B. Generated Files (Safe to Overwrite)

These are build artifacts:

```
book/index.html
book/toc.html
book/chapters/title.html
book/chapters/preface.html
book/chapters/chapter_*.html
```

These are fully regenerated each build.

Manual edits to these files will be lost.

---

## C. Compendium Page

```
book/chapters/compendium.html
```

Generated by:
```
data/generate_compendium_chapter.py
```

Book generator may patch navigation inside it.

Content changes must be made by editing the compendium generator or the compendium data JSON — not by editing the HTML output.

---

# 4. Script Contracts

## tweet_text_cleanup.py

Scope:
- Shared tweet text rendering module (imported by both generators)
- HTML entity decoding
- Media URL stripping (t.co links for embedded media)
- URL rendering with fetched titles, overrides, and endnotes
- Self-tweet URL stripping (when embedding as quote boxes)
- External tweet URL rendering as "tweet" + endnote
- Markdown-style emphasis: `*bold*` and `_italics_`
- Utility functions: `load_url_titles()`, `load_url_overrides()`

Must NOT:
- Add layout structure
- Add navigation
- Add CSS classes beyond tweet-text-level

---

## generate_compendium_chapter.py

Scope:
- Render singleton tweets
- Apply tag styling hooks
- Emit semantic HTML
- Include book-nav markup structure (class names only)

Must NOT:
- Reorder chapters
- Generate ToC
- Override chapter numbering

---

## generate_book_html_with_titles.py

Scope:
- Determine reading order
- Enforce chronological thread ordering
- Enforce chapter numbering
- Inject navigation
- Render front matter from fragments
- Patch compendium navigation
- Render self-tweet quote boxes
- Render media embeds (photos, videos, animated GIFs)
- Collect and render per-chapter endnotes for external tweet references

Must NOT:
- Duplicate text cleanup logic (uses tweet_text_cleanup.py)
- Modify raw JSON data
- Overwrite hand-edited files

---

# 5. Structural Invariants

These must always remain true:

- Cover → Title → ToC → Preface → Noteworthy Singletons → Thread Chapters
- Threads sorted chronologically by first tweet
- Chapter numbers start at 1 for Noteworthy Singletons
- Per-tweet dates are NOT displayed
- Chapter-level date appears as subtitle only
- Navigation exists at top and bottom of every page
- Navigation uses flex layout with:
  - `.nav-left`
  - `.nav-center`
  - `.nav-right`

---

# 6. Styling Rules

All styling must be done via CSS where possible.

`book/style.css` is hand-edited and must never be overwritten by generators.

Generators must:
- Emit semantic class hooks
- Avoid inline styles
- Avoid layout logic in Python

Key CSS hooks:

```
.page
.page-content
.chapter
.chapter-title
.chapter-subtitle
.book-nav
.nav-left / .nav-center / .nav-right
.nav-link / .nav-arrow / .nav-label
.tweet
.tweet-text
.tweet-media
.tweet-photo
.tweet-video
.quote-box / .quote-text
.chapter-endnotes
.endnotes-title
.endnotes-list
.endnote-item
.endnote-ref
```

---

# 7. What Must Never Happen

- No redesign of data pipeline without explicit instruction
- No silent refactoring of JSON formats
- No collapsing of cleanup + generation layers
- No automatic rewriting of frontmatter fragments
- No overwriting of book/style.css
- No destructive changes to raw export data

---

# 8. When Adding Features

Before modifying anything:

1. Identify which layer owns the change.
2. Confirm whether change is:
   - Text normalization
   - Structural layout
   - Navigation
   - Styling only
3. Modify only the owning layer.

If unsure, stop and ask.

---

# 9. Recommended Development Flow

1. Make small deterministic changes.
2. Regenerate.
3. Preview via local server.
4. Commit only after verifying navigation and structure.
